# 43 中国经济数据系统与可复核分析

[上一章：联合诊断](42-joint-diagnosis.md) · [目录](./) · [下一章：月报项目](44-monthly-report.md)

> 编写于 2026-10-03。附离线 Python 练习，官方历史摘录与教学数据分文件保存；没有运行定时采集，也没有将模拟数据标为当前值。

**前置阅读：**美国篇 [02 测量与口径](https://fangpings.github.io/us-econ/02-measurement.html)、[03 发布与版本](https://fangpings.github.io/us-econ/03-releases-and-vintages.html)，中国篇 [03 数据生产](03-data-production.md)、[04 发布与版本](04-releases-and-vintages.md)。本章不重复一般数据库教程，而是实现中国累计发布、版本修订和中美口径桥接所需的最小分析系统。

## 1. 自动分析最先自动化什么

先自动化重复、可检验的事情：保存原始文件，记录发布时间，检查单位、时期与范围，选择信息截止时点的版本，复算公式，列出缺失输入。机制判断仍要明确提出假设并核对证据。

抓到一个网页上的数，不表示抓到了正确的经济变量。页面可能同时放月值、累计值、同比和上年同期；图像中的注释还可能规定可比基数。把它们都读成一个 `value`，后续再精密的模型也只是算错得更快。

建议分四层：原件层保存 HTML、PDF 或表格与哈希；观察层保存逐条数字及来源定位；转换层保存公式、输入版本和结果；判断层保存结论、替代解释和待验证项。不要让自动生成的文字反过来覆盖原始记录。

## 2. 每个数字必须带哪些字段

| 字段 | 中国案例中的用途 |
| --- | --- |
| series_id | 区分开发投资、住宅投资、资本形成，不能只叫 investment |
| period_start / period_end | 区分 1—3 月累计、3 月单月与季末余额 |
| frequency / measure / unit | 月度或年度；金额、面积、同比或指数；亿元或万元 |
| scope | 全国或市辖区；全部商品房或住宅；合并集团或普通股 |
| method_version | 例如 M1 新旧口径、指数方法和贷款分类制度 |
| comparability_group | 经人工核查后可一起计算的范围与基数，不可自动臆测 |
| release_date / captured_date | 官方发布日与本系统实际整理日分开 |
| value / kind | 官方摘录或教学假设；缺失不能用零代替 |
| source_url | 指向原始发布，实际生产还要加文件哈希和页码/表名 |

股票还需收益类型、币种、复权和样本版本；利率还需期限、年化方式及借款群体；房价还需新旧房、城市范围、面积类别和季调状态。统一字段不等于可以删掉这些专属维度。

把单位写进字段而非只写列标题很重要：一宗土地成交表以万元记价，全国财政以亿元记价；一旦脱离原表，隐含单位就会丢失。

## 3. 发布日、观测期和抓取日不能合并

2024 年 GDP 的观测期截至 2024-12-31，初步值在 2025-01-17 发布，最终核实在 2025-12-26 发布。本练习在 2026-10-03 整理这些文件。四个日期各有作用。

[初步核算资料](https://www.stats.gov.cn/xxgk/sjfb/zxfb2020/202501/t20250117_1958332.html)与[最终核实公告](https://www.stats.gov.cn/xxgk/sjfb/zxfb2020/202512/t20251226_1962144.html)的现价 GDP 分别为 1,349,084 和 1,348,066 亿元，实际增速均为 5.0%。2025 年 6 月报告应选择初步版本，12 月 26 日收盘后复盘可以选择最终核实版本；名义水平变化与实际增速不变并不矛盾。

这套练习是依据存留发布重建信息集，不证明作者在 2025 年就已抓取归档。若研究盘中股价反应，还需精确到带时区的发布时分秒；这里的数据精度只有天，`as-of` 一律指该日结束，不能用于发布日盘中交易回测。

唯一键也要有版本：同一序列同一时期的两次发布应存两行。仅用“序列＋月份”作键，会把修订后的历史覆盖到早期报告，造成未来信息泄漏。

## 4. 累计数据转单月的四道门

设 1—2 月累计 180，1—3 月累计 300，同单位、同范围、同方法且基数可比，则 3 月金额为 120。但应在计算前检查：

1. 两个数真的是金额或面积累计，不是累计同比。
2. 起点同为当年 1 月，终点连续且为完整月末。
3. 单位、范围、方法和可比标签一致。
4. 没有尚未处理的名录变化、修订或特殊调整。

1—2 月合并发布不能凭空拆出 1 月与 2 月。累计同比也不能直接相减得到单月同比。官方同比可能用可比调整后的基数，数据商保存的上一年原发布绝对量未必是正确分母。

本章教学数据故意让 1—4 月累计 430 的可比标签变为 basis_B。虽然 430−300＝130 在算术上成立，程序应拒绝把它称为同口径 4 月值。系统不应为了“每月都能出图”偷偷忽略这个问题。

## 5. 可运行的离线练习

下载[完整练习包](/downloads/cn-econ-lab.zip)，解压后在该目录执行，需要 Python 3，示例只使用标准库：

```sh
python3 tools/econ_lab.py --as-of 2025-06-30
python3 tools/econ_lab.py --as-of 2025-12-31
python3 -m unittest discover -s tests -v
```

在仓库根目录执行相同命令也可以。第一条选出 GDP 现价值 **1349084**；第二条选出 **1348066**。两个历史版本仍在输入表里，程序只是改变选择，没有删除旧记录。输出同时保留单位、来源、方法、发布日期与假设类型。

[官方观察摘录 CSV](/downloads/observations.csv)与[教学累计数据 CSV](/downloads/teaching_cumulative.csv)分别保存。若要查看教学序列的某日可用记录：

```sh
python3 tools/econ_lab.py --input data/teaching_cumulative.csv --as-of 2025-04-30
```

下列交互式例子在解压目录运行，演示单月转换：

```python
from tools.econ_lab import read_rows, single_month
rows = read_rows('data/teaching_cumulative.csv')
print(single_month(rows[1], rows[0]))  # 120
single_month(rows[2], rows[1])        # 抛出 ValueError：可比标签不同
```

程序检查重复版本键、无效日期、空字段、非有限数字等，并对累计转换设置口径门槛。它没有自动判断官方两张表是否可比，`comparability_group` 仍需人依据原件确认；完整生产系统也需处理同日多次更正、缺失状态、撤回及源文件校验。

## 6. 从下载到月报的一次完整运行

第一步，固定信息截止时间和本次要回答的问题。例如“家庭需求与项目交付是否共同改善”，而非先抓所有能抓的数据。

第二步，从统计局、人民银行、财政部、外汇局、交易所或发行人原件进入。保存原始文件与提取位置，不能只保存搜索结果摘要。访问失败时记录失败，不把上期值伪装成新发布。

第三步，人工确认表头、附注和版本变化。对中国合并月份、累计同比、商品房与住宅、社融政府债、M1 修订设置专门检查。股票价格与全收益、新贷款与存量利率不得静默拼接。

第四步，生成截止时间内的观察快照，再运行有明确输入的转换。保留输入记录编号、公式和输出，不直接改原始值。任何转换被拒绝都进入本次报告的缺口清单。

第五步，报告事实、机制和待验证判断。自动文字必须引用实际使用的快照，而不是临时搜索到的新数据；所谓“超预期”需要真正的预期来源和截止时间，没有就只写实际增速。

第六步，发布前人工抽核关键数、图表轴、来源和结论；发布后保存报告版本。新修订到来时追加解释，不悄悄把旧判断改得永远正确。

## 7. 让中美映射成为可执行约束

映射表不应只有中文名和英文名。至少写清是否可以直接比、需要什么转换、哪些输入缺失。例如中国年度同比与美国季调环比折年率不能直接比较；社融不能只对应美国商业银行贷款；70 城新房指数不能只改名字就成为 FHFA HPI。

实务上将映射结果分为三类：可直接比较的同口径字段；需转换并保留公式的字段；只能并列解释、无法可靠数值桥接的字段。第三类不是分析失败，而是对数据边界的正确表达。

对“同名但不同总体”的序列，程序应像遇到不同币种一样显式拦截。后续研究者若决定构造近似，应创建新 series_id，注明假设，而非污染原始系列。
